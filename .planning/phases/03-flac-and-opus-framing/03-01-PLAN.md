# Phase 3 Plan 01: Preflight and Typed FLAC Config Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Track every checkbox and commit each task independently.

**Goal:** Prove candidate tooling is policy-compatible, then add only the dependency-free IAMF FLAC configuration model.

**Architecture:** Production code uses existing bit I/O for a fixed 38-byte prefix. Codec implementations remain outside the root graph; constructors derive canonical fields while readers preserve foreign values.

**Tech Stack:** Rust 1.85.0, `BitCursor`, `BitWriter`, cargo-deny 0.20.2.

**Spec:** `.planning/phases/03-flac-and-opus-framing/03-CONTEXT.md`; evidence: `.planning/phases/03-flac-and-opus-framing/03-RESEARCH.md`.

## Global Constraints

- IAMF v1.1.0; pre-encoded access units only; no runtime compression, decode, DSP, or resampling.
- Root normal graph stays exactly `iamf` and `thiserror`; no codec crate is added in this plan.
- Known short configs remain Raw; complete prefixes preserve bounded trailing bytes; parse never normalises.
- Every production read/write pair is adjacent and cited to a SHA-verified pinned source.

**Ten-path scope:** These ten paths are two coupled contracts, not one broad task: Task 1 owns only
the two preflight artifacts; Task 2 owns the production FLAC type plus its directly coupled exports,
dump arm, exact vectors, error-shape checks, and property generator. Neither task creates fixtures,
codec tooling, conformance wiring, dependency guards, or CI owned by later plans.
