Stand up both reference oracles and the fixture supply, on day one, off the code critical path.
Build `libiamf` natively at its pinned SHA so `iamfdec` runs in seconds while iterating; put
`iamf-tools` behind a digest-pinned container because Bazel + abseil + protobuf + fdk-aac is not a

exists**. The smoke decode of `test_000003.iamf` against `sawtooth_100_stereo.wav` validates the
oracle *and* the harness's comparison logic on a file we did not write. Everything plans 01-03
through 01-08 build is measured against machinery this plan has already demonstrated works.

**The non-obvious step, which the script must do and must comment.** `code/dep_codecs/lib/` ships
x86_64-Linux `.a` files (`libopus.a`, `libFLAC.a`, `libfdk-aac.a`) alongside Windows `.lib` files.
`CODEC_CAP=ON` is the default and does `find_library(... PATHS dep_codecs/lib NO_DEFAULT_PATH)`;
on macOS CMake **finds** them, compiles the codec sources in, and the link of `iamfdec` then fails
with hundreds of `ld: symbol(s) not found for architecture x86_64`. Create
`code/dep_codecs/lib_disabled/` and move `dep_codecs/lib/*.a` and `dep_codecs/lib/*.lib` into it so
the CMake probe fails cleanly and the codec source directories are excluded. Comment that Phase 3
will need real opus/FLAC libraries here and that the manifest records the disabled state precisely
so a Phase 3 build producing a different `iamfdec` hash is a visible manifest change rather than a
mystery. Configure with `cmake -DCMAKE_INSTALL_PREFIX="$PREFIX" -DBUILD_SHARED_LIBS=OFF .` in
`code/` — the static build means `iamfdec` needs no `DYLD_LIBRARY_PATH` at test time — then `make
-j` and `make install`; then a second, separate CMake project in `code/test/tools/iamfdec/` which

**The self-validating smoke test, which is the tracer's real verify.** After the build, run
`"$IAMFDEC" -i0 -o3 "$OUT/t3.wav" -r 16000 -s0 -d 16 -disable_limiter
".reference/libiamf/tests/test_000003.iamf"` and compare the result against
`.reference/libiamf/tests/sawtooth_100_stereo.wav`. Assert three things separately: the output file
exists and is larger than a 44-byte WAV header; the frame count is 8000; and the differing-sample
count is 0 of 16000. Each flag matters and the script must comment why — `-r 16000` because
`iamfdec` defaults to 48000 and would silently run the speex resampler on a 16 kHz file; `-s0`
because Sound System A (0+2+0) is that file's layout; `-d 16` so the WAV bit depth matches
`sample_size`; `-disable_limiter` because `IAMF_decoder_open()` unconditionally creates a −1 dBTP
peak limiter. **Do not treat exit code 0 as success**: `iamfdec` prints "can't opened." to stderr and
returns 0 when `-o3` is handed a directory, and a zero-sample decode also returns 0. The file
existence, the frame count and the sample-diff are the signals.
