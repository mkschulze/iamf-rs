<objective>
Make the encoder write `primary_profile = additional_profile = Base-Enhanced (2)` for any Mix
Presentation that contains a channel-based Audio Element whose first layer uses an expanded
loudspeaker layout (`loudspeaker_layout == 15`).

Today the crate writes Simple/Simple (0/0) for a lone expanded element. Research 260913-p28 section E
fed those files to pinned libiamf `iamfdec`. It **exits 0, decodes 0 frames and writes a bare 44-byte
WAV**. Patching only bytes 6-7 to `02 02` makes it decode 1 frame of 128 samples. This is a Core Value
bug.

Locked decisions from the orchestrator. They are non-negotiable:
- D-LOCKED REF: IAMF conformance comes from the reference implementations. `iamf-tools@v2.1.0`
  (`848c6ff4`) and pinned libiamf (`f06e919e`) decide disagreements. Disagreements are recorded.
- D-LOCKED IMPL: in `src/model/profile.rs` `select_minimum_profile`, select Base-Enhanced when any
  element's first layer is `LoudspeakerLayout::Expanded(_)`, and keep BOTH ceiling checks first.
  Add `// ref:` citations to:
  - iamf-tools@v2.1.0 `iamf/cli/profile_filter.cc:165-171` and `iamf/cli/obu_sequencer_base.cc:306-313`
  - libiamf `code/src/iamf_dec/IAMF_decoder.c:643-648` and `:1402-1410`
  - Eclipsa `FileExport.h:91-106`

  Add no new ErrorKind.
- D-LOCKED TESTS: migrate and add tests as research section D/F lists them:
  - tests/profile.rs: the 9.1.6-alone test becomes Base-Enhanced.
  - The `elements_totalling` users and the 16/17/18-channel tests are rebuilt on ambisonics elements.
  - `two_presentation_builder` becomes two 16-channel ambisonics elements.
