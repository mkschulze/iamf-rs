- The documented census (the old single-line `rg` pattern quoted in `CLAUDE.md:107`, `CONTRIBUTING.md:42`,
  `.claude/CLAUDE.md:170`, `clippy.toml:29`, `tests/error_shape.rs:7`, `.planning/codebase/CONVENTIONS.md:59`,
  `.planning/codebase/CONCERNS.md:67`) returns 0 hits (exit 1) on HEAD, because the sanctioned escape at
  `src/model/loudness.rs:94-95` is written `#[allow(` on line 94 and `clippy::disallowed_types,` on line 95. The
  documented command therefore cannot see the sanctioned escape and could not see a second multi-line one.
  Already recorded as deferred item 1 in `.planning/quick/260914-0sp-.../260914-0sp-deferred-items.md`.
- `tests/profile.rs` `exactly_one_float_lint_escape_exists_in_src_and_it_is_in_loudness_rs` is a line-based
  non-comment `contains("disallowed_types")` count and still passes (line 95). It stays as is (it runs on all four
  targets including Windows, where a bash script cannot be assumed); the new script is the stronger, documented
  census that also sees lint-group escapes.
- Clippy 1.85 experiment in the scratchpad (crate with `disallowed_types = "deny"` and `f64` banned): the lint was
  silenced by `#[allow(clippy::style)]`, by `#[allow(clippy::all)]` and by
  `#[cfg_attr(not(test), expect(clippy::disallowed_types))]`; only the unannotated function was reported. These are
  real escapes, so the census covers them.
- Prototype pattern (perl, verified on macOS perl 5.34 against HEAD and a scratch copy): after blanking lines whose
  first non-blank characters are `//` (newlines kept so line numbers stay right), the multi-line regex
  `\b(?:allow|expect)\s*\(\s*(?:[\w:]+\s*,\s*)*(?:(?:clippy::)?disallowed_types|clippy::(?:all|style))\b`
  reports exactly `src/model/loudness.rs:94` on HEAD; on the scratch copy it found the multi-line, single-line,
  `cfg_attr`+`expect`, inner `#![allow(clippy::style)]` and `allow(dead_code, clippy::all)` forms and ignored a
  `///` doc comment naming the attribute and a plain `#[allow(dead_code)]`.
- `tools/prove-guards.sh` runs in CI (`.github/workflows/ci.yml:251`, job `guardrails`, ubuntu). Nothing else
  asserts the count 6 besides the script's own `PASS_COUNT` gate; the count is stated in `CLAUDE.md:44`,
  `CONTRIBUTING.md:37`, `tools/CLAUDE.md:10`, the ci.yml comment at `:247` and the script header/summary.
- ripgrep is not known to exist on the ubuntu CI runner, and prove-guards must run there. perl is Essential on
  Debian/Ubuntu (`perl-base`) and ships with macOS, so the census uses perl, not `rg`.

Decisions (Claude's discretion, record them in the script header):
- One shared script, `tools/check-float-escape-census.sh`, mirroring the `--root PATH` style of
  `tools/check-codec-dependency-boundary.sh`. Docs and prove-guards both reference it, so they cannot drift.
- Coverage: `allow` and `expect`, outer `#[...]`, inner `#![...]` and inside `cfg_attr(...)` (the pattern is not
  anchored to `#[`), lint named with or without `clippy::`, anywhere in the lint list, plus the groups `clippy::all`
  and `clippy::style` that contain `disallowed_types`. The census is textual: it scans every `.rs` file under
  `src/`, registered as a module or not.
- Known limits, documented not fixed: `/* */` block comments are not stripped (a false positive fails loudly, never
  silently); an attribute generated by a macro is invisible to a textual scan.
- Exactly one, not "at most one": the tree has exactly one, and 0 means PROF-03's escape was lost.

Purpose: a guardrail that is documented but cannot fire is worse than none, because reviewers trust it.
Output: the census script, three new proof cases (9 PASS total), every census/count reference updated.
</objective>
