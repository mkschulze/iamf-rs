<objective>
Reject single-layer channel-based Audio Elements in `EncoderBuilder::build()` when their
`substream_count` or `coupled_substream_count` differs from what the loudspeaker layout requires.
Pinned `iamf-tools@v2.1.0` (`848c6ff4`) `decoder_main` rejects such elements with
"Coupled substream count different from the required number". The crate currently checks only
`substream_count + coupled_substream_count == channel_count`, so it writes Stereo 2/0, 5.1 6/0 and
7.1.4 8/4 files that the reference refuses. Research 260913-o3k probed 25 shapes and confirmed this.

Locked decisions from the orchestrator. Treat them as non-negotiable:
- D-LOCKED REF: conformance follows the reference implementations. `iamf-tools@v2.1.0` and the
  pinned libiamf decide disagreements. libiamf does not check coupling; iamf-tools does, and the spec
  (`index.bs:1002-1006`, "SHALL be coded in stereo mode") agrees with iamf-tools.
- D-LOCKED TABLE: the per-layout required `(substream_count, coupled_substream_count)` table is a
  `const fn` on `LoudspeakerLayout` in `src/model/layout.rs`. It cites
  `// ref: iamf-tools@v2.1.0 iamf/cli/obu_with_data_generator.cc ValidateSubstreamCounts / CollectBaseChannelGroupLabels`.
- D-LOCKED CHECK: the check lives in `validate_element_topology` (`src/encoder.rs`). The coupled
  count is checked first and fails with the new payload-free `ErrorKind::CoupledSubstreamCountMismatch`.
  The substream count is checked second and fails with the existing `ChannelCountMismatch`. The 32-byte
  Error assertion stays.
- D-LOCKED SCOPE: single-layer channel-based elements reachable through the builder, both standard
  and expanded layouts.
- D-LOCKED MIGRATION: do NOT move the `tests/encoder_streaming.rs` helpers to Expanded 3.0. Use
  Stereo 1/1 where a test does not need two substreams, and 5.1 4/2 where it does. Fix
  `tests/encoder_builder.rs` `element_with_layout` so 9.1.6 becomes 9/7. Add no new expanded-profile
  assertions.
- D-LOCKED TESTS: add a rejection test for every probe-confirmed wrong shape and a positive test for
  each layout's reference counts. Register the new kind in `tests/error_shape.rs`.
- D-LOCKED BOUNDARY: `tests/support/sequence_cases.rs` and `src/fuzzing.rs` keep Stereo 2/0 for
  low-level round-trip. The low-level writers, `src/obu`, goldens, DIFF-LEDGER.md and conformance
  fixtures do not change.
- D-LOCKED DEFER: write `260913-o3k-deferred-items.md`. Do not implement anything in it.
- D-LOCKED VERIFY: run fmt, clippy with and without `--features fuzzing`, the full
  `cargo test --locked`, doc tests, fuzz replay, and the conformance suite logged to
  `target/o3k-conformance.log`. Then run `git diff --quiet` on the unchanged paths.
- D-LOCKED HANDS-OFF: do not touch README.md, which already has an unrelated uncommitted
  modification, or the untracked `docs/` clones. Do not scan `target/` or `.worktrees/`.

Discretion choices:
- The function is named `single_layer_substream_counts`, not `substream_counts`. The reference table
  is valid only for the base channel group. When scalable layers are unblocked, their per-layer counts
  differ (research A3), and the name stops a future caller from misusing it.
- The tuple order `(substream_count, coupled_substream_count)` matches the argument order of
  `ChannelAudioLayerConfig::new`.
- The old combined `coupled > substream || sum != channel_count` clause is removed. A table
  self-consistency test proves that the two new equalities imply it.

Purpose: Core Value. The reference must accept every file the high-level encoder writes (API-01
static validation, API-05 single-layer channel-based constructors). CONF-06 is re-run as evidence.

Output: 1 const-fn table (2 impls), 1 error kind, 1 reworked topology check, about 4 new builder
tests, a migrated streaming helper set, and a deferred-items file.
