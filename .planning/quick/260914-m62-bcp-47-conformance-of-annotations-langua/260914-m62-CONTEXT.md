# Quick Task 260914-m62: BCP-47 conformance of annotations_language - Context

**Gathered:** 2026-09-14
**Status:** Ready for planning

<domain>
## Task Boundary

Check that every Mix Presentation `annotations_language` conforms to BCP-47 (IAMF v1.1.0 `index.bs:1273`
"SHALL conform to [[!BCP-47]]"). Resolves `260913-wlv-deferred-items.md` items 1 and 4.

</domain>

<decisions>
## Implementation Decisions

### Strictness level
- `validate()` reports a `Finding` at `Location::Field("annotations_language")` for a tag that is not
  well-formed (both `MixPresentation::validate` and therefore `DescriptorSet::validate` /
  `ParsedSequence::validate`).
- `EncoderBuilder::build()` rejects it with a new, dedicated unit `ErrorKind`
  (`AnnotationsLanguageNotWellFormed`, appended; `size_of::<Error>() <= 32`) at
  `Field("annotations_language")`, checked after `DuplicateAnnotationsLanguage` so existing duplicate
  tests keep their kind.
- Parsing stays tolerant and byte-exact (PARSE-04); no read or write rejection.

### Check scope
- RFC 5646 §2.1 ABNF well-formedness only, hand-written, no dependency, including the 17 irregular
  grandfathered tags and `x-` private use. Registered-ness is NOT checked (`qaa` is accepted).
- No extra §2.2.5/§2.2.6 duplicate-variant/singleton rules.
- Non-ASCII / non-UTF-8 bytes fail the grammar.

### Equality
- Keep ASCII-case-insensitive duplicate detection (RFC 5646 §2.1.1); no canonicalization; `en` and
  `en-US` are distinct.

### API
- The well-formedness function is `pub(crate)`; no new public API beyond the new `ErrorKind` variant.

### Claude's Discretion
- Placement of the grammar module, test file layout, finding message wording (must name BCP-47 /
  RFC 5646 and the offending tag), citations.

</decisions>
