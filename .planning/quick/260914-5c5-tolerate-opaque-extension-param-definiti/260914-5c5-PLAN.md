**Part A (Task 1).** `ParamDefinitionRegistry::observe_audio_element` (`src/obu/param_definition.rs:97-133`) decodes a
`ParamDefinition` prefix out of the opaque bytes of `AudioElementParam::Extension` and registers it. That has no source
behind it. The spec says parsers SHOULD ignore those bytes (`index.bs:772`, `:796`). `iamf-tools@v2.1.0`
`ExtendedParamDefinition` never reads the base class, and `CollectAndValidateParamDefinitions` skips it with `continue`.
`libiamf@v1.1.0` `IAMF_OBU.c` does `bs_skipABytes` and `continue`. All three sources agree, so no disagreement is recorded.

The registration causes three failures:
1. A legal empty or short extension aborts parse, write, `from_parts`, `SequenceWriter` and `build`.
2. Opaque bytes that happen to decode shadow a real Mix Gain id, so a valid file is rejected.
3. The nested duplicate-id findings in `DescriptorSet::validate` silently vanish.

The review suggested "decode if you can, otherwise don't register". Research rejected that because it keeps failure 2.
The fix is research option (b): never register. Blocks whose id appears only inside extension bytes become the existing
`UngovernedParameterBlock`.

**Part B (Task 2).** Seven model states write `Ok` but do not re-read as the same model. The probe confirmed each one on
HEAD. One review claim is refuted: `Extension{type 0}` round-trips, so it stays writable. No reader produces any of these
states, so rejecting them on write cannot change a parsed fixture, the golden file, a corpus seed or a generator. They are
refused before emission with two appended unit `ErrorKind`s. A property file proves "write `Ok` ⇒ equal re-read".

**Task 3** covers the docs and the release gates.

Research predicts no reference-hash change, including `test_000121` (the only extension param in 44 committed files,
`is_valid: true`). A scratch copy with fix (b) passed `parse_reference` (37 hashes) and `golden`.

Output: 2 code commits and 1 docs commit, plus an uncommitted SUMMARY and deferred-items file.
