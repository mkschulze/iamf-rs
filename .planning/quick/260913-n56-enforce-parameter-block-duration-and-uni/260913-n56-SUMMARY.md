# Quick 260913-n56 Plan 01: Enforce Parameter Block duration, parameter coverage and trim placement Summary

The high-level encoder now rejects, with six payload-free typed errors, mix-gain rates that differ from the output sample rate and Parameter Block durations that differ from the frame. It also rejects parameter substreams with gaps, late starts or duplicates, mid-stream start trims, and units after an end trim. Cross-unit state is committed only after a successful push.

## What changed

- **`src/error.rs`:** `ParameterRateMismatch` in the builder group. `ParameterBlockDurationMismatch`, `ParameterSubstreamCoverageMismatch`, `DuplicateTemporalParameterBlock`, `StartTrimAfterUntrimmedAudio` and `TemporalUnitAfterEndTrim` in the temporal group. All are unit variants, and `size_of::<Error>() <= 32` still holds (error_shape passes).
- **`src/encoder.rs`, `validate_declarations`:** P1 and P2 run after the `MultipleCodecConfigs` check. A private `output_sample_rate` (exhaustive match) and an `OPUS_OUTPUT_SAMPLE_RATE = 48_000` const support them. The `// ref:` block and DISAGREEMENT comment cite index.bs:863-865 / :1915 and iamf-tools `GetParameterBlockLinearMixGainsPerTick` / `GetNextParameterBlockTimestamps`. The `build()` doc links both kinds.
- **`src/encoder.rs`, `EncodingWriter`:**
  - New private `TemporalProgress { parameter_ids, start_trim_open, end_trimmed }`.
  - `preflight` returns `(TemporalUnit, TemporalProgress)`.
  - `push_temporal_unit` assigns `self.progress = next` only after `self.sequence.push_temporal_unit(&unit)?`.
  - T4/T3 run after the frames loop, so `TemporalUnitTrimMismatch` keeps precedence. P5 runs inside the parameter loop, P3 after the scratch `write_parameter_block` validation (so `SubblockDurationMismatch` keeps precedence), and P4 after the loop.
  - Doc comments on `push_temporal_unit`, `TemporalUnitInput::parameter_blocks` and `::trimming` describe the new rules.
- **Tests:**
  - 11 new streaming tests (2 in Task 1, 9 in Task 2) and 4 new builder tests.
  - The repaired `mode_1_submitted_blocks_require_non_empty_positive_exact_tiling` now uses duration 128 with subblocks 64+64.
  - 7 kinds added to the error_shape arrays (ParameterBlockDurationMismatch appears in both).
