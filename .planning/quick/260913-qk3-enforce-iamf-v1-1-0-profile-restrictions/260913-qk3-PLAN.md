<objective>
Enforce the IAMF v1.1.0 profile restrictions that quick 260913-p28 deferred: items 1-5 of
`260913-p28-deferred-items.md`. Each item is a vertical slice, and each lands as its own commit:

1. `build()` rejects a Mix Presentation whose `num_sub_mixes != 1` (item 1), or whose rendering config
   carries a reserved `headphones_rendering_mode` (item 2).
2. Minimum-profile selection follows the spec's scopes. The sequence-wide unique-element limits,
   Base's scene-based and multi-layer limits, and the sequence-wide Base-Enhanced 28-channel total all
   raise the profile (items 3 and 4).
3. `DescriptorSet::validate()` and `ParsedSequence::validate()` report a sequence whose header profile
   no Mix Presentation complies with, or whose sequence-wide limits exceed it (item 5).

Locked decisions (CONTEXT.md; the "LOCKED after research" block wins). They are non-negotiable:
- D-SPEC: satisfy BOTH the spec and the pinned references. Where the spec is stricter than
  `iamf-tools@v2.1.0` (`848c6ff4`) or `libiamf@v1.1.0` (`f06e919e`), the spec wins; where a reference
  is stricter, the reference rule stays. Record every disagreement in a `// ref:` / `// DISAGREEMENT:`
  comment. `SPEC_VERSION` stays "1.1.0".
- D-SCOPE: Simple/Base unique-element limits (1, 2) are sequence-wide (errata:1853, :1866).
  Simple/Base channel limits (16, 18) are per Mix Presentation (errata:1879, v1.1.0:1927).
  Base-Enhanced is at most 28 elements per Mix Presentation (v1.1.0:1951) and at most 28 channels in
  total across the sequence (v1.1.0:1953).
- D-A1: Base's "at most one scene-based" and "at most one channel-based element with num_layers > 1"
  are sequence-wide. Neither reference enforces them.
- D-ITEMS12: reject in `build()` with `SubMixCountNotOne` (which also rejects 0 sub-mixes) and
  `ReservedHeadphonesRenderingMode`. Both checks run before
  `validate_findings(declaration.presentation.validate())`. Use payload-free variants and
  `Location::Field`, and keep the 32-byte `Error` assertion.
- D-ITEMS34: split `select_minimum_profile` into a per-presentation floor and a sequence-wide floor
  over slices, so the builder and item 5 share one logic. Rename or invert
  `unrelated_presentations_do_not_sum_their_element_or_channel_limits` and
  `shared_element_is_counted_in_each_presentation_that_references_it` to the spec reading. Selection
  raises the profile; it rejects only when no profile allows the configuration.
- D-ITEM5: both `DescriptorSet::validate()` and `ParsedSequence::validate()` report no Mix
  Presentation complying with `primary_profile` / `additional_profile`, and any sequence-wide limit the
  header profile is exceeded by. Unique elements are counted without `obu_redundant_copy` duplicates.
  The writers (`SequenceWriter`, `write_sequence`, `write_parsed_sequence`) are not touched and add no
  write-time rejection.
- D-HASH: `test_000124.iamf`'s `semantic_sha256` may change: iamf-tools marks it `is_valid: false`
  (`test_000124.textproto:19`), and its only Mix Presentation has 2 sub-mixes under a Base header.
  Record the old and new hash and the reason in the commit message. If any OTHER reference
  expectation changes, stop and report instead of updating it.
- D-DEFER: write `260913-qk3-deferred-items.md` covering `build()` accepting zero Mix Presentations,
  `build()` accepting the same element twice in one sub-mix, separate sub-mix/headphones findings in
  `MixPresentation::validate()`, and item 6 (the Binaural rendering abort). Implement none of them.
- D-BOUNDARY: golden fixtures and DIFF-LEDGER.md stay byte-identical; CONF-05 and CONF-06 must still
  pass.
- D-HANDSOFF: never touch or stage `.claude/CLAUDE.md`, `.gitignore`, `.planning/PROJECT.md`,

Discretion choices (documented):
- Error names are `SubMixCountNotOne` ("a Mix Presentation must carry exactly one sub-mix") and
  `ReservedHeadphonesRenderingMode` ("headphones_rendering_mode is reserved"), at `Field("num_sub_mixes")`
  and `Field("headphones_rendering_mode")`. Any `Reserved(_)` is rejected, for every element type:
  v1.1.0:1341 drops the whole Mix Presentation.
- Items 1 and 2 get no separate `MixPresentation::validate()` finding (deferred, per D-DEFER). They are
  covered on the parse side by the item-5 compliance finding.
- The zero-presentation case fires the compliance finding, because v1.1.0:1929 requires at least one
  complying Mix Presentation. This extends one exact-count test in `tests/sequence_parse.rs`, and no
  reference hash.
- The additional_profile finding is emitted only when `additional_profile != primary_profile`.
  Otherwise it would repeat the primary finding verbatim. Profiles nest (Base-Enhanced ⊇ Base ⊇ Simple).
- Unique elements are distinct `audio_element_id`s, first wire binding. A redundant copy repeats its
  original's id (v1.1.0:1906 "unique if it only varies by the obu_redundant_copy flag"), so it is
  filtered by construction. A dedicated test proves it.
- For the sequence-limit finding on foreign input: when channel counting fails with
  `UnsupportedLayout` (a reserved type, layout or ambisonics mode), fall back to the count-only floor.
  The unique-element rules do not depend on channel counts.
- REQUIREMENTS.md API-03 ("never selects from the union of elements across unrelated Presentations")
  and API-04 ("multiple valid sub-mixes") contradict D-SCOPE and D-ITEMS12. They get an amendment note
  in place, and HANDOFF.md's per-presentation sentence is corrected. The checkbox status is unchanged.

Purpose: PROF-02 and the Core Value. A file this crate writes carries a profile header both the spec
and the pinned decoders accept (libiamf fails the Mix Presentation parse on `num_sub_mixes != 1`,
`IAMF_OBU.c:760-782`). Foreign files with non-compliant headers are reported, not rejected.

Output: two error kinds, two builder rejections, a spec-scoped profile core, profile findings in both
validators, migrated and new tests, two doc amendments and a deferred-items file.
