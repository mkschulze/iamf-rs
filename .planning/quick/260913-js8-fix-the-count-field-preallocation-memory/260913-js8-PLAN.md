<objective>
Close the CONCERNS.md "Allocation amplification from count fields" entry. Parsers currently reserve
capacity equal to an attacker-controlled count that was only checked against `bytes_remaining()`.
Inside the 2 MiB OBU cap, count x size_of::<Element>() can reach hundreds of MB per nesting level
before the first element read fails.

Remedy (one remedy, applied everywhere): a single crate-internal helper `bounded_vec::<T>(count)` in
`src/bits/reader.rs`. It reserves `min(count, MAX_PREALLOCATION_BYTES / size_of::<T>())` elements,
with `MAX_PREALLOCATION_BYTES = 1 << 16` (64 KiB). A Vec that needs more grows by push, so memory
tracks the elements actually decoded (each one consumed input bytes) and never the claimed count.
The existing `count > bytes_remaining()` checks and their exact error kinds/locations stay unchanged.
They keep early typed errors and fuzz-replay behaviour identical.

Audit result (grep of all of `src/`, excluding `target/` and untracked `docs/`). Sites fed by parsed values, all converted:
- `src/obu/mix_presentation.rs` read_mix_presentation (sub_mixes), read_strings, read_sub_mix (elements, layouts), read_loudness_info anchor elements (u8 count, already exact-byte-checked; converted for uniformity)
- `src/obu/audio_element.rs` read_counted (substream ids, params), read_scalable_channel_layout_config (layers, 3-bit count), read_ambisonics_config projection demixing_matrix
- `src/obu/param_definition.rs` read_param_definition subblock_durations
- `src/obu/parameter_block.rs` read_parameter_block subblocks, recon-gain layers (context length <= 7; converted for uniformity)
- `src/obu/audio_frame.rs` validate_temporal_unit `seen` (slice length; converted so `src/obu/` has one reservation idiom)
